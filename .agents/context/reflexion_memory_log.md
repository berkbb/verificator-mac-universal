# Reflexion Memory Log (Shinn et al., NeurIPS 2023)

This log records self-correction episodes, forensic calibration lessons, and architectural refinements across development sessions.

## Episode 1 — Eliminating False Positives on Legitimate Apps (2026-11-10)

- **Observation:** Naive timestamp delta checks (`Info.plist` vs executable modification time) and flagging any `@executable_path/*.dylib` or Objective-C runtime symbols caused false positives on legitimate apps (Electron apps, CMake/Homebrew bundles, and ad-hoc local builds).
- **Reflection:** Legitimate build pipelines sign or copy `Info.plist` and executables at different stages, and legitimate frameworks use Objective-C runtime functions internally. True tampering is characterized by **provenance/authority mismatch** (e.g., vendor frameworks signed by Apple Developer ID while the main executable is stripped to ad-hoc and linked against an unsigned/third-party dylib in `Contents/MacOS/`), or an explicit non-Apple self-signed authority (such as `TEAM EDiSO`) combined with Mach VM / swizzling hooks.
- **Corrective Action:** Recalibrated `ForensicScanner` into a 4-layer provenance-aware pipeline and verified **0% false positives** across 70+ real-world applications in `/Applications` and `~/Downloads`.

## Episode 2 — Full Parity with Sibling macOS Universal Apps (2026-11-10)

- **Observation:** The initial prototype used a flat `Sources/` layout without `VerificatorCore`, `SettingsView`, `AboutView`, `LogView`, `AppUpdateChecker`, or Graphify knowledge graph artifacts.
- **Reflection:** To match `Arhivar`, `Curatare`, `Copiator`, and `Redactor`, the project requires modular SwiftPM separation (`VerificatorCore` + `Verificator` + `VerificatorTests`), prominent UI Refresh (`⌘R`) actions, 4-tab `SettingsView`, `AboutView` with read-only `LicenseViewerSheet`, `LogView` (`⌥⌘L`), `.agents/` governance, and `graphify-out/` AST knowledge graph.
- **Corrective Action:** Refactored the repository into the modular architecture with full test coverage and Graphify integration.

## Episode 3 — Romanian Nomenclature & Clean Packaging Policy (2026-11-10)

- **Observation:** Sibling projects use single-word Romanian agent nouns without diacritics (`Arhivar`, `Copiator`, `Curatare`, `Descarcator`, `Paravan`, `Redactor`) under `com.babadogantech.<name>`. Furthermore, loose `.app` and `.zip` artifacts were polluting `dist/` and Downloads.
- **Reflection:** The application and repository must be renamed to `Verificator` (`com.babadogantech.verificator`, `verificator-mac-universal`). `dist/` must strictly hold signed release deliverables (`.dmg`, `.dmg.sig`, `SHA256SUMS.txt`), while `.app` stays strictly inside `build/Verificator.app`.
- **Corrective Action:** Renamed all targets, identifiers, and repository folder; removed `.zip` and `.app` from `dist/` and packaging scripts; prevented copying into `~/Downloads`.

## Episode 4 — On-Device AI & Quarantine Elevation (2026-11-10)

- **Observation:** Users needed forensic interpretation from on-device models, but silent fallbacks risked masking offline servers or missing models. Also, internet-downloaded apps carrying `com.apple.quarantine` required root-level clearing via `sudo xattr`.
- **Reflection:** Apple Intelligence should be the default first provider with Ollama and LM Studio as local alternatives (no cloud/embedding models). If a provider is offline or missing models, the UI must show an amber warning and refuse silent switching unless in "Automatic" mode. Quarantine should be dynamically detected and removable via Touch ID / admin password elevation. First-launch quarantine for Verificator itself must be clearly documented for Gatekeeper.
- **Corrective Action:** Implemented `ForensicAI` and `AIPrerequisites.providerProblem`, added in-window provider selector with amber warning labels, wired Touch ID `sudo xattr` elevation, and documented quarantine warnings across all markdown files.

## Episode 5 — Active Quarantine Calibration Against `/Applications` (2026-11-13)

- **Observation:** Across `/Applications`, already-opened apps such as `Audacity.app`, `Little Snitch.app`, `Menkul.app`, `RoCheck.app`, `Transmission.app`, `UPDF.app`, `Verificator.app`, and `Zed.app` still carry `com.apple.quarantine` xattrs with bit `0x0040` (`QTN_FLAG_USER_APPROVED`, e.g. `01c3`, `00c3`, `01c1`). Checking raw xattr existence with `getxattr(...) >= 0` falsely flagged all of them as quarantined and exposed the **Remove Quarantine** button when Gatekeeper had already cleared them.
- **Reflection:** macOS `URLResourceKey.quarantinePropertiesKey` treats `0x0040` (as well as `0x4000`/`0x8000`, mask `0xC040`) and malformed xattr values as inactive quarantine, and only inspects bundle roots/executables rather than non-executable resource files. Furthermore, `URL` caches resource values unless reset, and symlinks require checking both the link URL and `resolvingSymlinksInPath()`. `AppModel` must also validate live quarantine state on cache hits and clear `quarantineFeedback` when switching bundles.
- **Corrective Action:** Updated `ForensicScanner.hasQuarantineAttribute(at:executablePath:)` to query fresh `URLResourceKey.quarantinePropertiesKey` with raw flag parsing fallback (`isActiveQuarantineAttributeValue`), updated `AppModel` cache/feedback handling, and added `/Applications` quarantine calibration tests.

## Episode 6 — Top-to-Bottom Audit Fixes (2026-11-13)

- **Observation:** A full repository audit uncovered five concrete defects: (1) `AboutView` called `settings.t(.aboutPoweredBy)` without its `%1$@` argument, displaying literal `(%1$@)`; (2) `ContentView` reused `valueYes` (`"Mevcut (Stapled)"`) for `fieldQuarantine`; (3) `SettingsView` omitted the dedicated `Scan` tab despite `LKey.settingsScan` and 4-tab documentation; (4) `ForensicScanner` assumed standard `Contents/Info.plist` layout, missing Apple `WrappedBundle` apps (`Tapo.app`, `Xiaomi Home.app`) and reporting `0` byte sizes for `.framework` directories; (5) `AppModel.scan` lacked cancellation tokens for overlapping scans.
- **Reflection:** Every format-parameterized `LKey` must match call-site arity, semantic values (`Notarized` vs `Quarantined`) require distinct keys, bundle layout resolution must handle `WrappedBundle` and missing paths cleanly, and async UI state transitions must guard against superseded tasks.
- **Corrective Action:** Resolved wrapped bundle layouts and `.framework` binary sizes in `ForensicScanner`, added missing-bundle and internal `otool -L` dylib inspection, added localized quarantine/report keys across `tr`/`en`/`ro`, fixed `AboutView` format argument, restored 4-tab `SettingsView`, added scan cancellation in `AppModel`, and expanded `VerificatorTests`.

## Episode 7 — Expanding Targets & System Audits Without False Positives (2026-11-13)

- **Observation:** Extending `ForensicScanner` beyond `.app` bundles to `.framework` bundles and system directories revealed that Apple system frameworks under `/System/Library/Frameworks/` (such as `AppKit.framework`) reside in the dyld shared cache without an on-disk binary (`hasExec == false`), causing `/usr/bin/codesign` to print `"bundle format is ambiguous (could be app or framework)"` and trigger a false verification failure. Similarly, scanning system LaunchAgents/Daemons includes valid third-party helpers and scripts (e.g., `/bin/bash`).
- **Reflection:** Every expanded target kind (`.pkg`/`.mpkg`, `.dmg`, `.framework`, standalone Mach-O) and system audit surface (running processes via `proc_listallpids`/`KERN_PROCARGS2` and LaunchAgents/Daemons) must obey the same 0% false-positive invariant: missing disk binaries in system frameworks under `/System/Library/` must map to `CLEAN`, entitlement risk classification must stay strictly informational (`EntitlementAnalyzer`), and serialized `BundleAuditReport` JSON must decode pre-`1.3.0` archives cleanly via `decodeIfPresent` defaulting `targetKind` to `.appBundle`.
- **Corrective Action:** Added the dyld-shared-cache ambiguity guard in `ForensicScanner` (verified `AppKit.framework` evaluates `CLEAN`), added `AuditTargetKind` backward-compatible decoding, decoupled `EntitlementAnalyzer` from `IntegrityVerdict`, and validated `SystemAudit` across live macOS persistence plists and running PIDs with zero false positives.

## Episode 8 — Live Memory Inspection, Mach-O Filtering & Test-Suite Isolation (2026-11-13)

- **Observation:** Adding sibling-inspired live process mapped-region inspection (`proc_pidinfo(PROC_PIDREGIONPATHINFO)`), OCSP revocation checks, orphan child tracking (`ChildProcessGuard`), and automated SwiftUI accessibility/hardcoded-text lint tests uncovered two critical engineering traps: (1) naive `.framework/` or `.bundle/` substring matching on `PROC_PIDREGIONPATHINFO` hits mapped non-executable resources (`.pak`, `.car`, `.nib`), which would fail `SecStaticCodeCheckValidity` with false warnings; (2) sharing a global `ChildProcessGuard` PID file/slot table during parallel Swift Testing runs caused `terminateAll` in one test to race with `ForensicScanner.runTool` child processes in another test; and (3) `AccessibilityLintTests` caught an unlabeled icon-only swap button in `DiffView`.
- **Reflection:** Every mapped region candidate must be verified with `ForensicScanner.isMachOBinary(at:)` before code-signature inspection, process-guard test cases must use isolated `ChildProcessTracker` instances rather than mutating global signal-handler slots under parallel `@Test` execution, and automated UI lint guards (`HardcodedTextGuardTests`, `AccessibilityLintTests`, `BundleVerificationTests`) prevent localization and VoiceOver regressions at compile/test time.
- **Corrective Action:** Filtered `LiveProcessInspector.isCandidateMappedLibrary` with `isMachOBinary`, extracted instance-isolated `ChildProcessTracker`, added missing `.accessibilityLabel` across `ContentView`, `SettingsView`, and `DiffView`, and verified 0 false positives across 72 live processes and 65 `/Applications` bundles.

## Episode 9 — Sibling Security Suite Integration, Synthetic Bundle Sign-Off & Live Calibration
- **Incident / Observation:** Adding a Unicode RTLO spoof character inside a copied `/bin/echo` synthetic `.app` with a modified `Info.plist` caused `codesign --verify` to fail with a broken resource seal (`TAMPERED`), masking the `OpenSafety` `WARNING` branch.
- **Root Cause:** Rewriting `Info.plist` inside an already-signed Apple binary invalidates its code directory seal unless re-signed for test isolation.
- **Corrective Action:** Re-signed the synthetic `OpenSafety` test `.app` with `codesign --force --sign - --deep` before running `ForensicScanner` so the test cleanly exercises `OpenSafety` warning emission, and ran release CLI calibration verifying 0 false positives across 65 `/Applications` (64 clean, 1 known tampered `UPDF`, 1 quarantined `AnyDesk`), 73 running processes (73 clean), and 39 persistence items (35 clean, 3 missing keystone targets, 1 quarantined `GoogleUpdater`, 0 tampered).

## Episode 10 — Finder Right-Click Services (`NSSendFileTypes`), Batch Empty-State Centering & Universal Home Copy (2026-11-13)
- **Observation:** Three UX/integration defects appeared in live desktop testing: (1) empty states inside **Toplu Paket Denetimi** rendered left-aligned despite `ContentUnavailableView`; (2) the Finder context-menu service (**Verificator ile Denetle**) did not match/trigger on Finder items; and (3) main window prompts, header subtitle, and action buttons still advertised `.app` bundles exclusively even though `.dmg`, `.pkg`, `.framework`, `.dylib`, Mach-O binaries, and folders are supported.
- **Root Cause:** (1) `batchAuditView` wrapped `ContentUnavailableView` inside a root `VStack(alignment: .leading, ...)` without expanding `.frame(maxWidth: .infinity, maxHeight: .infinity)`; (2) `Support/Info.plist` declared only legacy `NSSendTypes` (`NSFilenamesPboardType`, `public.file-url`, `NSStringPboardType`) without `NSRequiredContext` (`<dict/>`) or `NSSendFileTypes` (`public.folder`, `public.item`), duplicate `build/Verificator.app` entries remained in `pbs`/`LaunchServices`, `servicesProvider` wasn't registered in `applicationWillFinishLaunching`, and `AppModel.handleIncomingURL` dropped unsupported files silently instead of producing `unsupportedTargetReport`; (3) primary localization keys (`appSubtitle`, `actionSelectApp`, `statusIdle`, `statusIdleHint`) were not updated when non-`.app` targets were added.
- **Corrective Action:** Centered both `batchAuditView` empty states; updated `Support/Info.plist` `NSServices` to `NSRequiredContext = <dict/>` + `NSSendFileTypes = ["public.folder", "public.item"]` (matching working sibling apps `Arhivar`/`Copiator`), hardened `AppDelegate.extractServiceTargetURLs(from:)` and cold-launch registration, handled directory containers/unsupported items in `AppModel.handleIncomingURL`, updated trilingual copy 1:1 across `tr`/`en`/`ro`, and refreshed `/Applications/Verificator.app` + `pbs -flush && pbs -update` while unregistering `build/Verificator.app`.

## Episode 11 — Unified Multi-Format Batch Directory Scans & Multi-Selection Finder Service Routing (2026-11-13)
- **Observation:** Folder batch scans (`ForensicScanner.auditDirectory` / `--batch`) inspected `.app` bundles only (skipping `.dmg` and `.pkg`/`.mpkg` installers in Downloads/installer folders), and selecting two or more items in Finder Services only forwarded the first item.
- **Corrective Action:** Refactored `ForensicScanner` to collect `batchAuditableExtensions` (`app`, `dmg`, `pkg`, `mpkg`) via `batchTargets(in:)` and share a single parallel worker pipeline `auditTargets(_:)` across folder sweeps and multi-item Finder invocations, while routing 2 comparable Finder selections directly to `AppModel.openDiff(baseline:target:)` and 3+ selections/folders to multi-target Batch Audit via `AppModel.handleIncomingURLs(_:)`.

## Episode 12 — Large-Bundle Signature Verification Timeouts & Zero False-Positive Guarantee (2026-11-14)
- **Observation:** Auditing `/Applications/Xcode.app` (`128,917` sealed resources) produced a false-positive `TAMPERED` verdict (`findingVerifyFailedTitle`) with `Process timed out after 20s`. Additionally, `spctl --assess` took `~26.5s` against `Xcode.app`, exceeding `assessGatekeeper`'s 15s default timeout, and `runTool`'s `.utility`-QoS timeout work item could be delayed under heavy parallel load.
- **Root Cause:** `ForensicScanner.runTool` terminated processes exceeding `timeoutSeconds: 20` with exit code `-3` (`"Process timed out after 20s"`), and `auditMachOBundle`, `auditDiskImage`, `auditStandaloneMachO`, `auditInstallerPackage`, and `SystemAudit.inspectProcessExecutable` treated any non-zero verification exit code as a signature integrity failure (`CRITICAL` / `TAMPERED`) without distinguishing the `-3` timeout sentinel.
- **Corrective Action:** Raised verification timeouts (`bundleVerifyTimeoutSeconds = 180s`, `pkgVerifyTimeoutSeconds = 120s`, `executableVerifyTimeoutSeconds = 60s`, `defaultGatekeeperTimeoutSeconds = 90s`), scheduled `runTool` watchdogs at `.userInitiated` QoS with explicit `cancelledToolExitCode` (`-2`) precedence, centralized outcome evaluation in `CodeSignatureVerificationOutcome`, `evaluateVerifyResult`, `verifyCodeSignature`, `appendVerificationFindings`, and `appendGatekeeperFindings` so any genuine tool timeout maps strictly to a `.warning` (`findingVerifyTimedOutTitle`, `findingSpctlTimedOutTitle`) with 1:1 `tr`/`en`/`ro` parity, added unit test coverage, and verified all 53 tests pass plus `/Applications/Xcode.app` evaluates to `CLEAN` with `--spctl`.

## Episode 13 — Kernel Sockets Fallback on macOS 26, JIT W^X Calibration & Seatbelt Integration Testing (2026-11-14)
- **Observation:** During implementation of Group 1 and Group 2 features: (1) XNU `net.inet.tcp.pcblist_n` / `udp.pcblist_n` returned `48`-byte header-only buffers (`0` PCBs) to unprivileged ad-hoc binaries on macOS 26 (Darwin 25/27); (2) legitimate W^X JIT standalone binaries (such as Bun-based `claude-agent-acp`) triggered `TAMPERED` when `_mach_vm_protect` and `_sys_icache_invalidate` symbols were treated identically to injected dylibs; (3) creating internal relative test symlinks with `URL(fileURLWithPath: "A")` resolved relative to CWD instead of relative `"A"`; and (4) running live `/usr/bin/codesign` / `/Applications` integration tests inside a Seatbelt terminal sandbox failed with `CSSMERR_TP_NOT_TRUSTED` and `Authority=(unavailable)` because sandbox blocks `trustd`/`securityd`.
- **Corrective Action:** Added automatic Darwin `libproc` (`PROC_PIDLISTFDS` + `PROC_PIDFDSOCKETINFO`) socket enumeration fallback in `KernelSocketList`; restricted `mach_vm_protect` / `_sys_icache_invalidate` injection heuristics to dylibs (`isDylib == true`) while keeping standalone JIT executables clean; used `withDestinationPath: "A"` in `BundleSymlinkAudit` tests; and verified all 61 tests in 9 suites pass, rebuilt/installed `/Applications/Verificator.app` (`arm64` + `x86_64`), and verified `verificator-cli /Applications/Xcode.app` (`CLEAN`), `--posture --json` (`106` receipts audited), and `--running` (`536` processes, `0` tampered, `23` sockets, `19` listening).

## Episode 14 — APFS Signed System Volume Boot FileVault Detection Calibration (2026-11-14)
- **Observation:** Unsandboxed execution on macOS 26/27 returned `false` for `URLResourceKey.volumeIsEncryptedKey` on `/` and `/System/Volumes/Data`, and `diskutil info /` reported `Encrypted: No` alongside `FileVault: Yes`, causing `SystemSecurityPostureAuditor` (`--posture --json`) to emit `fileVaultBootEncrypted: false` and `VolumeEncryptionInfo` to label the boot drive `Unencrypted` on `/Applications/Xcode.app` despite `fdesetup status` reporting `FileVault is On.`.
- **Corrective Action:** Added deterministic `VolumeEncryptionInfo.parseFdesetupStatus(_:)` and `VolumeEncryptionInfo.parseDiskutilFileVault(_:)` parsers plus a 10-second `NSLock`-cached boot FileVault fallback (`/usr/bin/fdesetup status` then `/usr/sbin/diskutil info /`) strictly scoped to boot/system volume paths (`/` and `/System/Volumes/*`) so external `/Volumes/*` drives still flag unencrypted removable media cleanly, updated `SystemSecurityPostureAuditor`, added unit assertions in `Group1And2Tests`, passed all `61/61` tests in `9` suites, rebuilt and reinstalled universal `/Applications/Verificator.app`, and verified live `--posture --json` (`fileVaultBootEncrypted: true`), `/Applications/Xcode.app` (`CLEAN`, `Volume: Macintosh HD (APFS, Encrypted)`), and `--running` (`624` processes, `0` warnings/tampered, `25` sockets).
